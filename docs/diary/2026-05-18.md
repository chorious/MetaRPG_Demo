# 2026-05-18 日记

今天是 MetaRPG v0.6.6 的原语日。从早晨到深夜，6 个本体论原语全部落地。

一开始的任务是"恢复"——把之前被简化掉的 Safe fallback 架构重新搭起来。 refusal_fallback 的 4 套模板、writer_agent 的 5 个 mode 路由、feasibility 的 4 分支世界响应、runner 的 Bold-first → Safe(Qwen) 决策树。这一步比预想的顺利，235 个已有测试一个没破，说明之前的测试覆盖是扎实的。

但真正有意思的工作从下午开始：6 个原语不是 6 个独立功能，而是一张约束网。

**时间流动**是最先落地的。world_time {turn, hour, day} 本身只是一个字典，但它的价值在于 story_packet 把 current_time 暴露给 Writer，而 Writer 的 system prompt 加了一段 TIME AWARENESS。这意味着同一个 Mara，turn 1 的早晨和 turn 10 的深夜，LLM 看到的约束不同。这不是硬编码的 schedule，而是 LLM 在原语约束下的自由创作。

**实体生命周期**紧跟着上来。EntityState(energy, mood, life_state, last_seen_turn, last_seen_location) 给每个 NPC 加了 soft 状态。energy 每 turn 衰减 0.05，cross 0.3 变 tired，cross 0.1 变 exhausted。这个数值本身不重要，重要的是 story_packet 的 npc_surface 现在会把 energy 和 mood 暴露给 Writer。Writer 看到 energy=0.45 的 Mara，描写方式应该和 energy=0.95 时不同。

**固化 + 双层知识**是一起做的。Fact.fact_type 标签让 crystallize 能区分 location/entity_appearance/prop/event。belief_tracker 的贝叶斯更新规则很简单：每次证据 ±0.15，0.85 坍缩为 fact，0.15 删除。但这里有一个我现在还没完全解的问题：belief 的"证据"从哪来？目前 belief_tracker.update_belief() 存在且可测，但 runner 里只有一个占位注释。真正触发 belief 更新的，需要 Translator 能识别叙事中"玩家追问某话题"这类行为。这个点留到 playtest 时再看数据决定。

**传说冲突**是我最喜欢的一个设计。detect_conflict 的启发式很简单：同 predicate、同 args[0]、不同 args[1]。但关键是"不删除任何一方"。world.lore_conflicts 记录矛盾对，story_packet 暴露给 Writer，Writer prompt 说"你可以让 NPC 犹豫、改口、被质疑，但不要主动解决"。这个机制让 LLM 有了创作空间——矛盾本身就是叙事燃料。

**离场推演**是最后一个。offscreen_tick 检查 last_seen_turn < current_turn - 1 的实体，跑 tick 并生成一句 ambient 描述。code-only 回退路径让没有 LLM 时也能工作：低 energy → "looks exhausted"，中等 energy → "has been keeping busy"。story_packet.scene.ambient_events 把这些描述注入，Writer prompt 说"自然织入开场，不做焦点"。

6 个原语接入 runner 的顺序经过仔细考虑：

```
offscreen_tick (F) → batch1[Bold+Feasibility] → audit → decision → commit
→ crystallize (D) → belief_tracker (C) → advance_time (A) → tick_entity (B)
```

这个顺序的逻辑是：离场推演先跑，这样 Writer 看到的 ambient 是最新的；commit 后 crystallize 提取新 fact，这些 fact 立即进入世界知识；然后时间推进、实体衰减。下一 turn 的 story_packet 会完整反映所有这些变化。
